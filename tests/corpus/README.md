# `tests/corpus` — ground truth for `doc-router-bench`

`manifest.json` says, for every document in the corpus, **which pages actually need OCR**.
`doc-router-bench` classifies each document with each judge and compares page by page, so
the manifest is the only thing that decides whether a judge is right.

Nothing else reads this directory. It is not part of the golden tests, it does not affect
`cargo build`, and the fixtures it points at are owned by `tests/fixtures/`.

## Schema

```json
{
  "documents": [
    {
      "file": "../fixtures/mixed.pdf",
      "source": "synthetic",
      "page_count": 4,
      "needs_ocr": [1, 3],
      "note": "text, image, text, image."
    }
  ]
}
```

| field        | type       | meaning |
|--------------|------------|---------|
| `file`       | string     | Path to the PDF, **resolved relative to this manifest's own directory** (absolute paths are used as-is). |
| `source`     | string     | Free text. Documents are grouped by it in the report; `"synthetic"` is treated specially (see below). |
| `page_count` | integer    | Pages the document really has. Checked against the classifier — see "The page_count check". |
| `needs_ocr`  | `[int]`    | **0-indexed** page numbers that need OCR. Every other page in `0..page_count` is expected to stay local. |
| `note`       | string?    | Optional. Why this document is in the corpus. |

Unknown fields are rejected. That is deliberate: a manifest with `"need_ocr"` instead of
`"needs_ocr"` would otherwise parse as "no page needs OCR" and quietly score every judge
against wrong truth.

## Page numbering: 0-indexed, always

`needs_ocr` uses the same numbering as everything else in doc-router: `pages_needing_ocr`,
`ocr_reasons`, `PageVerdict::page`, `--pages` on the CLI. The first page is `0`.

pdf-inspector, the underlying library, is 1-indexed. doc-router normalises that exactly
once, inside `classify`. Do not apply a second conversion here — write page numbers the way
`doc-router classify` prints them and they will line up.

A page number `>= page_count`, or a repeated one, is rejected when the manifest loads.

## The `page_count` check

If the classifier reports a different page count than the manifest declares, that document
is **excluded from the score** and the run exits non-zero. It is not a warning.

A wrong `page_count` means the `needs_ocr` list describes a *different* document — a page
was added, or the list is 1-indexed by mistake. The judge would then be scored against the
wrong pages, and every number in the report would look plausible and mean nothing. That is
the most dangerous failure mode this harness has, so it fails loudly instead.

A judge scoring *badly* is not a failure: it is a result, and the exit code ignores it.

## What is in here today

Nineteen documents in two groups: ten `"synthetic"` fixtures and nine `"adversarial"` ones.

**`"synthetic"`** — the ten fixtures from `tests/fixtures/`, hand-derived from the `SPECS`
table in `tests/fixtures/make_fixtures.py`: a page built with a text content stream does not
need OCR, a page built as a bare image XObject does.

- `empty.pdf` **is** included. It is a structurally valid 0-page PDF, doc-router classifies
  it cleanly, and it is the edge case where every rate has an empty denominator — the
  harness should survive it, so it is scored rather than hidden.
- `not_a_pdf.bin` is **not** included. It has no per-page truth to state: it is not a
  document, and its purpose (in the golden tests) is to prove the parser rejects it.

## The synthetic caveat

When a judge scores perfectly across the synthetic group, the report says in as many words
that this measures **non-regression only**. Those pages either carry text operators or carry
none, which is exactly the signal the heuristic reads, so no judge can do better and no two
judges can be told apart there.

## `"adversarial"` — where the text layer lies

`adversarial/` holds nine documents, 56 pages, generated by `adversarial/make_adversarial.py`
(same conventions as `tests/fixtures/make_fixtures.py`: deterministic, `--force`, a hash line
per file). Every page is one where the *structural* signal and the *real* content disagree,
so the page has an unambiguous ground truth that pdf-inspector's page list gets wrong. On
this group `--judge heuristic` scores 28 missed and 9 wasted out of 56 pages.

Four traps, one per class, plus honest pages beside them:

| trap | the page | inspector | truth |
|------|----------|-----------|-------|
| bad OCR layer | a scan with a hidden text layer whose transcription has confused characters, dropped lines and fused words | clear — it counts the text operators | needs OCR |
| broken `/ToUnicode` | a text page whose font carries a valid CMap that maps every letter to its Cyrillic neighbour: correct on screen, mojibake on extraction | clear | needs OCR |
| chrome over a scan | a scan whose only text is running head, folio and file reference | clear — twelve operators clear its ten-operator floor | needs OCR |
| watermarked text | a complete, correct text layer under a full-page `RECEIVED` stamp | flagged — a full-page image and a body under that same floor | does **not** need OCR |

`honest_mixed.pdf` is the control: clean text pages alternating with honest scans, no trap at
all. The heuristic routes it exactly, which is the point — the group is not rigged.

Three things are worth knowing before you add to this directory.

- **The traps sit on a threshold, not on a hunch.** pdf-inspector flags a page with a
  full-page image when it has fewer than ten text-showing operators. "Chrome over a scan"
  therefore needs *ten to forty-nine* operators to slip past, and "watermarked text" needs
  *fewer than ten* to be caught. Same rule, opposite sides. Two of the five classes exist in
  the shape they do because of that one number.
- **A missing `/ToUnicode` would not work.** pdf-inspector already flags an Identity-H font
  with no `/ToUnicode`, and a Type3-only page. The CMap has to be *present and wrong*.
- **The watermark case cannot be shown by extraction, only by the verdict.**
  `doc-router extract` returns nothing for those pages: pdf-inspector's extractor consults
  the same full-page-image signal and blanks the markdown it did read. The text really is
  there — any other extractor returns it in full — so the ground truth stands, and the
  suppression is a second symptom of the same wrong signal rather than evidence against it.

### Ground-truth text: `<name>.truth.json`

Every document has a sibling truth file giving the exact text a perfect extractor should
return, keyed by 0-indexed page number as a string. `manifest.json`'s `needs_ocr` lists are
generated from these, so the two cannot drift.

```json
{
  "schema": "doc-router/corpus-truth@1",
  "document": "tounicode_mixed.pdf",
  "page_count": 5,
  "needs_ocr": [1, 3, 4],
  "pages": {
    "0": {
      "needs_ocr": false,
      "trap": "none",
      "kind": "clean",
      "why": "Ordinary text page: the text layer is the page.",
      "text": "SITE INSPECTION REPORT -- PAGE 1\nThe supplier shall ...",
      "text_layer": "SITE INSPECTION REPORT -- PAGE 1\nThe supplier shall ..."
    }
  }
}
```

| field | meaning |
|-------|---------|
| `schema` | Version tag. Bump it if the shape changes; nothing parses this file yet. |
| `document` | The PDF this describes, as a file name in the same directory. |
| `page_count` | Pages in the PDF. Must equal the manifest's `page_count`. |
| `needs_ocr` | The 0-indexed pages whose `pages.<n>.needs_ocr` is true, for convenience. |
| `pages.<n>.needs_ocr` | Whether page `n` needs OCR. This is the ground truth the bench scores against. |
| `pages.<n>.trap` | Which trap the page carries: `none`, `bad_ocr_layer`, `broken_tounicode`, `sparse_decorative_text`, `watermarked_text`. |
| `pages.<n>.kind` | The generator's page kind, for reproducing one page in isolation. |
| `pages.<n>.why` | One paragraph: what the structural signal sees, and why the truth is what it is. |
| `pages.<n>.text` | **The reference text.** Everything a perfect extractor should return for the page, including text that exists only inside the raster. |
| `pages.<n>.text_layer` | What the PDF's *own* text layer holds: equal to `text` on a clean page, garbled on a bad-OCR page, Cyrillic on a mojibake page, furniture-only on a chrome page, and `null` on an honest scan that has no text layer at all. |

The gap between `text` and `text_layer` is the whole corpus: where they differ, the page
needs OCR, and where they are equal it does not.

### Regenerating

```
python tests/corpus/adversarial/make_adversarial.py            # writes nothing that differs
python tests/corpus/adversarial/make_adversarial.py --force    # rewrites
```

Output is byte-stable for a given pypdf and Pillow. A changed hash with no change to the
script means one of those two moved; re-check `page_count` in `manifest.json` before
committing it.

## Adding a real document

The adversarial group is built rather than found, which bounds what it can show: the traps
are the ones a generator can state exactly, at the sizes and thresholds pdf-inspector uses
today. Real documents are still worth adding, and they go in the same way.

To add one:

1. Put the PDF somewhere — **it does not have to be in this repo**. Paths are resolved
   relative to this manifest, so `../../../scans/invoice.pdf` or an absolute path both work,
   and documents that cannot be committed (customer data, licensed samples) can still be
   scored. Only commit a PDF here if it is genuinely redistributable.
2. Run `cargo run -p doc-router-cli -- classify <file>` to get its page count, and read the
   pages yourself to decide which ones need OCR. Do not copy the classifier's
   `pages_needing_ocr` into `needs_ocr` — that would make the judge its own ground truth.
3. Add an entry with `"source": "real"` (or any label you want to group by) and a `note`
   saying what makes the document hard.
4. Run `cargo run -p doc-router-bench` and check the document is scored, not excluded.

A manifest kept outside the repo works the same way:
`cargo run -p doc-router-bench -- --corpus /path/to/your/manifest.json`.
